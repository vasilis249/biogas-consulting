# Ενσωμάτωση SCADA — πλάνο

> Στόχος: οι τιμές που ήδη μετρά το SCADA της μονάδας (ενέργεια, ώρες ΣΗΘ και πυρσού, ροή
> βιοαερίου, CH₄, θερμοκρασίες, πιέσεις, στάθμες) να μπαίνουν **αυτόματα** στην πλατφόρμα.
> Ο χειριστής δεν ξαναγράφει αριθμούς, μόνο ελέγχει και επιβεβαιώνει. Οι κρίσιμες καταστάσεις
> (trip ΣΗΘ, υπερπίεση, πτώση θερμοκρασίας) γίνονται συναγερμοί σε πραγματικό χρόνο.
>
> Κατάσταση: **πλάνο, δεν έχει υλοποιηθεί**. Κανένα βήμα δεν απαιτεί αλλαγή στο SCADA του πελάτη.

---

## 1. Αρχές (μη διαπραγματεύσιμες)

1. **Μόνο ανάγνωση.** Η πλατφόρμα δεν στέλνει ποτέ εντολές στο SCADA/PLC. Τον έλεγχο της
   μονάδας τον κάνει μόνο το SCADA. Ούτε «write-back» ούτε setpoints από το cloud.
2. **Μόνο εξερχόμενες συνδέσεις από τη μονάδα.** Κανένα ανοιχτό port προς το δίκτυο
   αυτοματισμού (OT). Ο gateway της μονάδας στέλνει δεδομένα προς τα έξω με HTTPS. Τίποτα
   από το internet δεν μπορεί να συνδεθεί προς τα μέσα.
3. **Ο gateway κάθεται σε DMZ / ξεχωριστό VLAN**, ανάμεσα στο δίκτυο OT και στο internet,
   με λογαριασμό μόνο ανάγνωσης στο SCADA (OPC UA user με δικαιώματα read).
4. **Τα δεδομένα από το SCADA δεν αντικαθιστούν σιωπηλά τον χειριστή.** Οι ημερήσιες τιμές
   μπαίνουν ως **πρόχειρο** και τις επιβεβαιώνει ο χειριστής (ή διορθώνει, με καταγραφή).
5. **Αν πέσει το internet ή ο gateway, η μονάδα δεν επηρεάζεται.** Ο gateway κρατά τοπική
   ουρά και στέλνει ό,τι έλειψε όταν επανέλθει η σύνδεση. Η πλατφόρμα βγάζει συναγερμό
   «χάθηκε η επικοινωνία με το SCADA».

## 2. Αρχιτεκτονική

```
 ┌──────────── ΜΟΝΑΔΑ (δίκτυο OT) ────────────┐        ┌────────────── CLOUD (Supabase, EU) ──────────────┐
 │ PLC / SCADA (WinCC, Ignition, ...)          │        │                                                  │
 │   OPC UA · Modbus TCP · SQL historian · CSV │        │  Edge Function  scada-ingest                     │
 │                │ (read-only)                │ HTTPS  │   · έλεγχος κλειδιού ανά gateway (hash)          │
 │                ▼                            │ ─────▶ │   · επικύρωση / κλίμακα / μονάδες                │
 │  Gateway (DMZ): Node-RED ή Telegraf         │ μόνο   │   · scada_readings (5′ τιμές)                    │
 │   · διαβάζει tags κάθε 1′                   │ προς   │   · κανόνες πραγματικού χρόνου → raise_alert()   │
 │   · τοπική ουρά αν πέσει το internet        │ έξω    │  pg_cron (κάθε ημέρα 06:00):                     │
 │   · στέλνει πακέτα κάθε 1–5′                │        │   · ημερήσιο σύνολο → production (πρόχειρο)      │
 └─────────────────────────────────────────────┘        │  UI: «Σήμερα» με ζωντανές τιμές, επιβεβαίωση     │
                                                        └──────────────────────────────────────────────────┘
 Εναλλακτικά (χωρίς gateway):  εξαγωγή CSV/Excel από το SCADA → ανέβασμα στην εφαρμογή (Φάση 1)
                               cloud κατασκευαστή ΣΗΘ / SCADA → API connector (Φάση 4)
```

### Τρόποι σύνδεσης, από τον απλούστερο

| Τρόπος | Τι χρειάζεται στη μονάδα | Συχνότητα | Πότε |
|---|---|---|---|
| **A. Αρχείο CSV/Excel** (εξαγωγή αναφοράς του SCADA) | Τίποτα, μόνο όποιος κατεβάζει την αναφορά | ημερήσια | Αμέσως, για όλους· εφεδρική λύση |
| **B. Αρχείο αυτόματα** (το SCADA γράφει CSV σε φάκελο ή στέλνει email/SFTP) | Ρύθμιση εξαγωγής στο SCADA | ωριαία/ημερήσια | Όταν το SCADA έχει προγραμματισμένες αναφορές |
| **C. Gateway OPC UA / Modbus TCP → HTTPS** | Μικρό βιομηχανικό PC στο DMZ | 1–5′ | **Κύρια λύση**: ζωντανές τιμές + συναγερμοί |
| **D. Ανάγνωση από SQL historian** του SCADA | Gateway με πρόσβαση read-only στη βάση | 1–5′ | Όταν το SCADA κρατά ήδη ιστορικό σε SQL |
| **E. API του cloud του κατασκευαστή** (ΣΗΘ ή SCADA) | Τίποτα, μόνο συμβόλαιο/κλειδί API | 5–15′ | Όταν ο πελάτης έχει ήδη τέτοιο portal (π.χ. της μηχανής) |

Gateway: δύο ώριμες επιλογές ανοιχτού κώδικα, ανάλογα με τον πελάτη:
- **Node-RED** με κόμβους OPC UA και Modbus: οπτική ρύθμιση, εύκολο για τεχνικό του πελάτη.
- **Telegraf** με input plugins OPC UA / Modbus και έξοδο HTTP: ένα αρχείο ρυθμίσεων, ελάχιστοι πόροι.

Και στις δύο περιπτώσεις **εμείς δίνουμε έτοιμο πρότυπο ρυθμίσεων** (flow / `telegraf.conf`).
Ο πελάτης συμπληρώνει μόνο διευθύνσεις και tags από το φύλλο αντιστοίχισης (§4).

## 3. Τι παίρνουμε από το SCADA (ελάχιστο σετ ανά χωνευτή / ΣΗΘ)

| Μέγεθος | Τύπος tag | Πού πάει στην πλατφόρμα |
|---|---|---|
| Μετρητής kWh ηλεκτρικής (σωρευτικός) | counter | `production.kwh_el` (διαφορά ημέρας) |
| Μετρητής kWh θερμικής | counter | `production.kwh_th` |
| ΣΗΘ σε λειτουργία (0/1) ή ωρόμετρο μηχανής | state / counter | `production.chp_hours`, συναγερμός trip, **συντήρηση ΣΗΘ** (ωρόμετρο) |
| Πυρσός σε λειτουργία (0/1) | state | `production.flare_hours`, συναγερμός «πυρσός > Χ h» |
| Ροή βιοαερίου (m³/h) ή μετρητής m³ | gauge / counter | `production.biogas_m3` |
| CH₄ % (αναλυτής αερίου) | gauge | `production.ch4_pct` (μέσος σταθμισμένος με τη ροή) |
| H₂S ppm (μετά την αποθείωση / είσοδο μηχανής) | gauge | συναγερμός H₂S, τάση |
| O₂ % | gauge | συναγερμός (κίνδυνος μίγματος) |
| Θερμοκρασία χωνευτή | gauge | `production.digester_temp_c`, κανόνας −1 °C/ημέρα σε **πραγματικό χρόνο** |
| Πίεση / στάθμη αεριοθαλάμου | gauge | συναγερμός υπερπίεσης, «Σήμερα» |
| Στάθμη δεξαμενής χωνεύματος | gauge | ημέρες αυτονομίας (εκκρεμότητα του review) |
| Τροφοδοσία: ζυγός / μετρητής αντλίας (αν υπάρχει) | counter | πρόταση για την ημερήσια τροφοδοσία (ο χειριστής επιβεβαιώνει υποστρώματα) |
| Γενικός συναγερμός SCADA / κουμπί έκτακτης ανάγκης | state | συναγερμός `scada` → ειδοποίηση κινητού (Wave C) |

Ο κατάλογος είναι **σταθερός στην πλατφόρμα**. Κάθε μονάδα αντιστοιχίζει τα δικά της tags σε
αυτά τα μεγέθη, ώστε οι αναφορές και οι κανόνες να δουλεύουν ίδια για όλους τους πελάτες.

## 4. Μοντέλο δεδομένων (migration 0013 — προτεινόμενο)

```
scada_sources   id, tenant_id, unit_id?, name, kind ('gateway'|'file'|'vendor_api'),
                key_hash, last_seen_at, last_error, enabled
scada_tags      id, tenant_id, source_id, unit_id, metric (από τον κατάλογο §3),
                address (π.χ. ns=3;s=CHP1.Energy ή 40001), value_type ('counter'|'gauge'|'state'),
                scale, offset, eng_unit, enabled
scada_readings  tag_id, ts, value          — 5′ τιμές, πίνακας με partition ανά μήνα
scada_daily     tag_id, day, min, max, avg, first, last, delta, on_hours   — μόνιμο ιστορικό
production      + source ('manual'|'scada'|'file'), + confirmed_by, + confirmed_at
alerts.kind     + 'scada'
```

- **Όγκος:** 30 tags × 288 τιμές/ημέρα ≈ 8.600 γραμμές/ημέρα ανά μονάδα, περίπου 3 εκ./έτος.
  Τα κρατάμε 90 ημέρες σε ανάλυση 5′. Το `scada_daily` μένει για πάντα, για αναφορές και τάσεις.
- **Ασφάλεια:** RLS όπως σε όλους τους πίνακες. Το `scada-ingest` δεκτικό μόνο με κλειδί ανά
  gateway (αποθηκεύεται hash, ακύρωση με ένα κλικ), όριο ρυθμού, έλεγχος ότι κάθε tag ανήκει
  στον πελάτη του κλειδιού. Τα tags/sources τα ρυθμίζει μόνο ο admin.
- **Counters:** η διαφορά ημέρας υπολογίζεται με ανίχνευση μηδενισμού/αλλαγής μετρητή
  (αρνητική διαφορά = reset). Μέγιστο λογικό όριο από την ισχύ ΣΗΘ (ίδιο με τη φόρμα παραγωγής).
- **Ποιότητα:** κάθε τιμή εκτός φυσικών ορίων (ίδια με τα CHECK της 0010/0011) απορρίπτεται και
  καταγράφεται στο `last_error` του source. Δεν μολύνει ποτέ τις αναφορές.

## 5. Φάσεις

| Φάση | Περιεχόμενο | Αξία για τον πελάτη | Μέγεθος |
|---|---|---|---|
| **0. Discovery** | Ερωτηματολόγιο ανά μονάδα (§6), φύλλο αντιστοίχισης tags (Excel), έλεγχος δικτύου / IT | Ξέρουμε τι υπάρχει πριν αγοράσει κανείς υλικό | S (1–2 ημέρες ανά μονάδα) |
| **1. Εισαγωγή αρχείου** | «Εισαγωγή από SCADA» στην Παραγωγή: ανέβασμα CSV/Excel → προφίλ αντιστοίχισης στηλών ανά μονάδα → προεπισκόπηση → πρόχειρες εγγραφές → επιβεβαίωση | Τέλος η πληκτρολόγηση. Δουλεύει **χωρίς υλικό** και με οποιοδήποτε SCADA | M |
| **2. Gateway + ingest** | Migration 0013, Edge Function `scada-ingest`, πρότυπα Node-RED / Telegraf, οθόνη «Σύνδεση SCADA» (sources, tags, τελευταία επικοινωνία), ημερήσιο pg_cron → πρόχειρη Παραγωγή, ζωντανές τιμές στη «Σήμερα» | Ζωντανή εικόνα, αυτόματη ημερήσια παραγωγή, ωρόμετρο ΣΗΘ για τη συντήρηση | L |
| **3. Συναγερμοί πραγματικού χρόνου** | Κανόνες: ΣΗΘ σταμάτησε > 5′ χωρίς προγραμματισμένη στάση, πυρσός > Χ h, υπερπίεση, θερμοκρασία −1 °C, H₂S/O₂, «χάθηκε επικοινωνία > 15′». Σύνδεση με τις ειδοποιήσεις κινητού (Wave C) | Ο χειριστής μαθαίνει το trip στο κινητό σε λεπτά, όχι το πρωί | M (μετά τη Wave C) |
| **4. Connectors κατασκευαστών** | Ανάγνωση από cloud API κατασκευαστή ΣΗΘ / SCADA, όπου ο πελάτης έχει ήδη συμβόλαιο | Χωρίς υλικό στη μονάδα | S–M ανά κατασκευαστή |

Σειρά: **0 → 1** άμεσα (μικρό ρίσκο, άμεση αξία). Η **2** ξεκινά με έναν πιλοτικό πελάτη που
έχει OPC UA ή Modbus TCP. Η **3** έρχεται μαζί με τη Wave C (ειδοποιήσεις κινητού).

### Τεστ (όπως σε κάθε φάση)
- SQL: ingest με λάθος κλειδί / ξένο tag / τιμές εκτός ορίων, reset μετρητή, ημερήσιο άθροισμα,
  πρόχειρη παραγωγή που δεν πατάει επιβεβαιωμένη, RLS, fresh == upgrade.
- Edge Function: tests με stub δικτύου (όπως το `send-alerts`).
- Gateway: προσομοιωτής OPC UA / Modbus σε container στο CI, με τα πρότυπα ρυθμίσεων.
- Demo: προσομοιωμένο SCADA στο `mock.js` (ζωντανές τιμές, trip ΣΗΘ) + E2E.

## 6. Ερωτηματολόγιο ανά μονάδα (Φάση 0)

1. Ποιο SCADA / HMI και έκδοση; Ποιος το συντηρεί (κατασκευαστής μονάδας, integrator, εσωτερικά);
2. Ποιο PLC; Είναι διαθέσιμο **OPC UA server** ή **Modbus TCP**; Υπάρχει SQL historian;
3. Βγάζει το SCADA αναφορές (CSV/Excel/PDF); Μπορεί να τις στέλνει αυτόματα (email, φάκελος, SFTP);
4. Η μηχανή ΣΗΘ έχει δικό της portal / cloud του κατασκευαστή; Υπάρχει πρόσβαση API;
5. Λίστα tags με διεύθυνση, μονάδα μέτρησης και κλίμακα για τα μεγέθη του §3 (συμπληρώνεται στο φύλλο αντιστοίχισης).
6. Δίκτυο: υπάρχει internet στη μονάδα; firewall/DMZ; ποιος εγκρίνει νέα συσκευή στο δίκτυο OT;
7. Απαιτήσεις κυβερνοασφάλειας του πελάτη ή του ασφαλιστή (π.χ. πολιτική για συσκευές στο OT).
8. Ποιος στη μονάδα είναι υπεύθυνος για τον gateway (τηλέφωνο για εφημερία);

## 7. Κυβερνοασφάλεια & κανονιστικά (να ελεγχθούν ανά πελάτη)

- Σχεδίαση κατά τις πρακτικές IEC 62443 για συστήματα αυτοματισμού: ζώνες/αγωγοί, ελάχιστα
  δικαιώματα, μόνο εξερχόμενη επικοινωνία, ενημερώσεις του gateway, καταγραφή.
- **NIS2:** να ελεγχθεί αν ο πελάτης (παραγωγός ενέργειας) εμπίπτει στην εθνική ενσωμάτωση της
  Οδηγίας (EU) 2022/2555 με βάση μέγεθος και δραστηριότητα. Αν ναι, ο gateway και η πλατφόρμα
  μπαίνουν στη διαχείριση κινδύνου του πελάτη. **Να επιβεβαιωθεί από το επίσημο κείμενο**, όχι
  από αυτό το έγγραφο.
- Σύμβαση: ρόλος μας ως εκτελών την επεξεργασία (DPA), μαζί με το DPA του Supabase.

## 8. Αποφάσεις που χρειάζονται

1. **Ποιος πελάτης είναι ο πιλότος;** Ιδανικά με SCADA που έχει OPC UA ή Modbus TCP.
2. **Υλικό gateway:** το προμηθεύουμε εμείς (τυποποιημένο, προρυθμισμένο) ή το IT του πελάτη;
3. **Τιμολόγηση:** η σύνδεση SCADA ως ξεχωριστή υπηρεσία (εγκατάσταση + μηνιαία συνδρομή);
4. **Ποιοι κατασκευαστές SCADA / ΣΗΘ** εμφανίζονται συχνότερα στους πελάτες, για να
   προτεραιοποιήσουμε πρότυπα gateway και connectors (Φάση 4).
